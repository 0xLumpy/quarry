## Release contract

`v0.3.10` is an integrity release, not a feature release. It must establish that Quarry:

1. never reports successful acquisition before primary evidence is durably settled;
2. never mutates a sealed base run;
3. never certifies a revision, manifest or campaign outcome it cannot reconstruct;
4. preserves an honest, bounded and replayable disposition for work it could not retain or execute;
5. launches the artifact and credential set that policy actually approved;
6. permits intended private-target, broad-active and public-OOB behavior while withholding scanner,
   metadata and unrelated control-plane destinations;
7. makes private operator output lossless and does not invent conclusions from absent evidence;
8. ships with reproducible, non-live release gates and basic public-project integrity.

No implementation may close a row by reducing the accepted Nuclei request set, default-denying private
targets, disabling public Interactsh, imposing a small universal time limit, or discarding target evidence.

## Required implementation order

This order minimizes transitional formats and makes each gate meaningful:

1. Freeze release inputs and sanitized regression oracles; do not alter source engagement runs.
2. Close `V310-01` and `V310-02` first: evidence settlement and repository authority are prerequisites.
   Their shared implementation contract is
   [`PHASE-1-EXECUTION-REPOSITORY.md`](../design/PHASE-1-EXECUTION-REPOSITORY.md).
3. Build `V310-03` and `V310-04` on that boundary; do not add another sidecar format.
4. Close independent `V310-05` while the state work proceeds.
5. Close `V310-06` and publish the honest supported envelope.
6. Close `V310-07` and `V310-09` without changing the accepted defaults.
7. Close the minimum correctness subset in `V310-08`; keep the larger report redesign deferred.
8. Close `V310-10`, cut a clean candidate and run every gate below from that exact commit.

## Version and publication rule

The following must all be true before changing `0.3.9`:

- every in-scope work package is `CLOSED` with evidence;
- every applicable gate is green from the exact candidate commit;
- all deferred limitations are accurately documented in operator-facing release notes;
- no unresolved stop-ship row remains in `CURRENT-HEAD.md`;
- the maintainer explicitly approves the version bump and publication.

Only then update the package/version sources in a dedicated release commit, rebuild from that commit,
record artifact digests, tag it, and publish. Until then, `v0.3.10` is a plan—not a released state.
